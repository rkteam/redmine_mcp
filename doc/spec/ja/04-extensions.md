# 他プラグイン向け拡張 API

[Deutsch](../de/04-extensions.md) | [English](../en/04-extensions.md) | [Español](../es/04-extensions.md) | [Français](../fr/04-extensions.md) | [Italiano](../it/04-extensions.md) | [日本語](04-extensions.md) | [한국어](../ko/04-extensions.md) | [Polski](../pl/04-extensions.md) | [Português (Brasil)](../pt-BR/04-extensions.md) | [Русский](../ru/04-extensions.md) | [中文](../zh/04-extensions.md)

## 概要

Redmine MCP は、他のインストール済み Redmine プラグインが独自のツール、リソース、プロンプトを登録し、既存ツールを拡張できる拡張メカニズムを提供します。

## 目的

MCP サーバーの重複や Redmine MCP コードの変更なしに、Redmine プラグインを AI と統合する単一のアプローチを提供すること。

## 影響範囲

- プラグイン
- API
- 権限

## ビジネスルール

### 自動検出

- Redmine 起動時（MCP が有効な場合）、システムはインストール済みのすべてのプラグインをチェックする。
- 次のいずれかのパスに `mcp.rb` ファイルがある場合、プラグインは MCP 拡張を持つとみなされる:
  - `lib/<plugin.id>/mcp.rb`;
  - `lib/<plugin directory basename>/mcp.rb`;
  - 識別子が `redmine_` で始まる場合は `lib/<plugin.id without redmine_ prefix>/mcp.rb`（典型例: `redmine_advanced_checklists` → `lib/advanced_checklists/mcp.rb`）。
- `redmine_mcp` プラグインは拡張として自身を読み込まない。
- 設定で MCP 拡張チェックボックスがオフのプラグインはスキップされる。
- 1 つのプラグインの拡張が失敗しても、拡張ファイルの構文エラーを含め、他のプラグインの読み込みはブロックされない。

### ツール登録

- 拡張プラグインは任意の数のツールを登録できる。
- 各ツールには、名前、説明、入力スキーマ、出力スキーマ、権限要件、ハンドラーがある。
- 完全なツール名: `redmine_<plugin_id>_<name>`（例: `redmine_redmine_advanced_checklists_get_issue_checklists`、`redmine_advanced_search_semantic_search_issues`）。
- ツール名の重複は禁止される。
- ツールは、対応する権限を持つユーザーの MCP にのみ表示される。
- 課題スコープの拡張ツールは、有効な Redmine プロジェクトモジュールを要求できる（モジュール識別子はプラグイン id と一致する必要はない）。`tools/list` では、そのモジュールを持つ少なくとも 1 つの可視プロジェクトで宣言された権限をユーザーが持つ場合にツールが表示される。モジュール要件がない場合、少なくとも 1 つの可視プロジェクトでの権限で十分である。呼び出し時は特定の課題を再チェックする: 可視性、そのプロジェクトでの権限、有効なモジュール; そうでなければ応答は "not found" である。
- MCP 読み取り専用モードの拡張書き込みツールはハンドラーを実行しない: 拒否はコア書き込みツールと同じである。

### 既存ツールの拡張

- プラグインは既に登録されたツールを拡張できる。
- 拡張は次を行える:
  - 追加の入力パラメータを追加;
  - メインハンドラーの前にコードを実行;
  - ハンドラー後にコードを実行し、結果を変更。
- 複数のプラグインが同時に同じツールを拡張できる。
- 追加パラメータは共有入力スキーマにマージされる。
- 追加パラメータ名は、コアツールパラメータまたは同じツールの他の拡張パラメータと一致してはならない。
- 結果のスキーマは `tools/list` 公開前に正規化される。
- 拡張の実行順序はプラグインの読み込み順序と一致する。

### リソース登録

- プラグインは一意の URI でリソースを公開できる。同じ URI の再登録は拒否される。
- リソースには読み取りハンドラーが必要である。
- 推奨 URI スキーム: `redmine://<plugin_id>/<type>/<id>`。
- リソースは権限チェックを要求できる; 権限がない場合リソースは利用不可である。
- 権限チェックは URI と引数を受け取る。プロジェクトは `project` / `project_id`、URI（クエリまたは `/projects/:id` セグメントの `project`/`project_id`）、または拡張が定義する明示的なプロジェクトリゾルバから取得される。`resources/read` はチェックに `{uri: ...}` を渡す。
- 呼び出しでプロジェクトが指定されているが、現在のユーザーに見つからないまたはアクセス不可の場合、アクセスは拒否される。「少なくとも 1 プロジェクト」チェックは、プロジェクトが指定されていない場合（空引数での検出）のみ適用される。
- リソースの読み取りはテキストまたは JSON 形式で内容を返す。

### プロンプト登録

- プラグインは名前、説明、引数、ハンドラー付きでプロンプトを追加できる。
- 完全なプロンプト名: `redmine_<plugin_id>_<name>`。
- プロンプトは対応する権限を持つユーザーが利用できる。権限チェックは `project` / `project_id` を含む呼び出し引数を受け取る。プロジェクトが指定されているが見つからないまたはアクセス不可の場合、アクセスは拒否される; プロジェクト未指定の場合はリソースと同じ検出ルールが適用される。

### イベント（フック）

- プラグインは MCP ライフサイクルイベントを購読できる（例:
  - ツール登録;
  - リソース登録;
  - プロンプト登録;
  - すべての拡張の読み込み完了）。
- イベントハンドラーのエラーはログに記録され、メインプロセスを中断しない。

### 依存関係

- 拡張プラグインは Redmine MCP へのハード依存を宣言する必要はない。
- 登録前に `RedmineMcp::ExtensionApi` / `mcp_extension_enabled?` をチェックすることを推奨する。
- 拡張プラグインは MCP gem を含める必要はない — Redmine MCP API で十分である。

### Extension API の機能

Extension API を通じて、拡張プラグインは次を行える:

- MCP が有効で拡張が無効化されていないことを確認;
- ツールを 1 回だけ登録（リロード時の重複なし）;
- 標準権限チェックと課題検索付きの課題スコープツールを登録; ハンドラー実行前に課題が消失した場合、応答は内部エラーではなく "not found" である;
- パラメータと before/after ハンドラーで既存のコアツールを拡張;
- `redmine_get_mcp_info` の capability モードを登録（例: `issue_search.semantic`）;
- `internal_request` を通じて現在のユーザーとして Redmine またはプラグイン REST API をプロセス内で呼び出す（`GET`、`POST`、`PUT`、`PATCH`、`DELETE`; 対象エンドポイントは API 認証を受け付ける必要がある）; REST エラーは内部リクエスト HTTP ステータスなしで正規 MCP コードにマッピングされる;
- `{ ok, data | error }` エンベロープ形式で `outputSchema` を公開する。

Ruby API メソッドリストとコード例はプラグイン README および [mcp_tool_development.md](mcp_tool_development.md)（開発ガイド、behavioral SPEC ではない）に記載されている。

## エッジケース

- 拡張ファイルのないプラグインは無視される。
- 拡張ファイルが存在するが `require` が失敗する場合 — ログエントリ、拡張は読み込み済みとみなされない; ツール登録は成功した `require` の副作用である。
- 存在しないツールの拡張試行 — 拡張登録時にエラー。
- 設定で MCP 拡張チェックボックスがオフのプラグインは、拡張ファイルが存在しても読み込まれない。
- 新しい拡張のインストール後、Redmine 再起動が必要; MCP クライアントは再接続が必要な場合がある。

## エラー処理

- 拡張ファイル読み込みエラー — ログエントリ、他プラグインの読み込みを継続。
- 起動時のツール登録エラー — ログエントリ。
- 拡張 `before` ハンドラーのエラー — ツール実行を中止。
- `after` ハンドラーのエラー — ログに記録; ハンドラーが制御フローを変更しない限り、メインハンドラー結果は保持される。

## テストシナリオ

8. 空引数でのリソースとプロンプトの検出は、少なくとも 1 プロジェクトで権限がある場合引き続き利用可能である。
9. `redmine_*` のような `plugin.id` と `lib/<id without redmine_ prefix>/mcp.rb` ファイルを持つプラグインは MCP 統合ありとみなされ、MCP 拡張設定に表示される。
10. モジュール要件を持つ課題スコープツールは、別プロジェクトで権限を持っていても、そのモジュールを持つ可視プロジェクトがないユーザーの `tools/list` には含まれない。
