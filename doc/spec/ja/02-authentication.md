# 認証と認可

## 概要

MCP へのアクセスは標準の Redmine API キー認証を使用します。すべての操作はキーの所有者であるユーザーとして実行されます。

## 目的

MCP が Redmine セキュリティを迂回しないこと、およびユーザーが許可された操作のみを実行できることを保証すること。

## 影響範囲

- 権限
- API
- ユーザー

## ビジネスルール

### 認証

- `/mcp` にアクセスするには Redmine REST API が有効である必要がある。
- API キーは `X-Redmine-API-Key` ヘッダーで渡す（JSON リクエストボディやクエリ文字列からは取得しない）。
- アクティブなユーザーのキーのみ受け付ける。
- キーがない、または無効なキーのリクエストは拒否される。

### グローバル MCP 権限

- ユーザーはグローバル **Use MCP** 権限（`use_mcp`）を持つか、Redmine 管理者である必要がある。
- `use_mcp` 権限は **管理 → ロールと権限** で必要なロールに手動で有効化する。
- 管理者は常に MCP アクセスを持つ: 標準の Redmine グローバル権限チェックにより、ロールに関係なく管理者は許可される。
- `use_mcp` のない他のユーザーは、有効な API キーがあってもリクエストは拒否される。

### ツール権限

- 各ツールには独自の Redmine 権限要件がある。
- ツールは、ユーザーが使用権限を持つ場合のみ `tools/list` に表示される。
- ツール呼び出し時に権限が再チェックされる。
- データは Redmine の可視性ルール（プロジェクト、課題、メンバー）でフィルタされる。

### リソースとプロンプトの権限

- リソースとプロンプトには独自の権限要件がある場合がある。
- 権限がない場合、リソースまたはプロンプトはリストされず、読み取れない。
- リソースとプロンプトの権限チェックは URI と入力引数（`project` / `project_id` を含む）を考慮する。引数でプロジェクトが指定されていない場合、少なくとも 1 つの可視プロジェクトでの権限で十分である。
- 拡張は URI と引数からプロジェクトを解決する明示的なルールを定義できる。

## エッジケース

- 非アクティブユーザーは、以前発行されたキーがあっても MCP を使用できない。
- 管理者は `use_mcp` の個別割り当てなしで MCP アクセスを持つ。
- エンティティスコープの権限チェックを持つツール（例: 課題）は、ユーザーが少なくとも 1 つのプロジェクトで対応する権限を持つ場合、空の引数でも `tools/list` に表示される場合がある。
- そのようなツールが Redmine プロジェクトモジュールも要求する場合、「少なくとも 1 プロジェクト」とは、ユーザーが権限を持ち、指定モジュールが有効な可視プロジェクトを意味する。モジュール要件がない場合、少なくとも 1 つの可視プロジェクトでの権限で十分である。`tools/list` への存在は特定の課題への権限を意味しない: 権限とオブジェクトの可用性は呼び出し時に再チェックされる。

## エラー処理

| 状況 | 結果 |
|----------|-----------|
| REST API 無効 | HTTP 401 |
| 無効または欠落した API キー | HTTP 401 |
| Use MCP 権限なし | HTTP 403 |
| 特定ツールの権限なし | `tools/list` からツール不在; 直接呼び出し — "Permission denied" エラー |
| ユーザーに利用不可のエンティティ | エラー説明付きツール応答（例: "Issue not found"） |

## テストシナリオ

1. 有効なキーと Use MCP 権限のリクエスト — 正常アクセス。
2. API キーヘッダーなしのリクエスト — HTTP 401。
3. Use MCP 権限のない非管理者キーのリクエスト — HTTP 403。
4. `use_mcp` のないロールの管理者キー — 正常アクセス。
5. ユーザーは権限のあるツールのみ `tools/list` で確認できる。
6. アクセス不可課題のツール呼び出しはエラーを返し、他ユーザーのデータは返さない。
7. プロジェクトモジュール要件を持つ課題スコープツールは、権限を持つがモジュール有効な可視プロジェクトがない場合 `tools/list` に表示されない; そのようなプロジェクトがある場合は表示される。
