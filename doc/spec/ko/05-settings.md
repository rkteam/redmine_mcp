# 설정 및 로깅

## 개요

Redmine MCP 플러그인은 표준 Redmine 플러그인 설정 인터페이스를 통해 구성됩니다. MCP 작업은 추가로 로깅됩니다.

## 목표

관리자가 MCP 활성화 및 개별 플러그인의 MCP 통합 활성화를 제어할 수 있게 합니다.

## 영향을 받는 영역

- 설정
- UI
- 플러그인

## 비즈니스 규칙

### 설정 매개변수

설정은 **Administration → Plugins → Redmine MCP → Configure**에서 사용할 수 있습니다.

| 매개변수 | 기본값 | 설명 |
|----------|--------------|----------|
| Enable MCP | off | `/mcp` 엔드포인트를 활성화 또는 비활성화합니다. 활성화 시 설치된 플러그인의 MCP 확장이 자동으로 로드됩니다 |
| Read-only mode | off | 쓰기 도구 및 쓰기 작업을 차단합니다 |
| MCP extensions | all enabled | MCP 통합이 있는 설치된 플러그인 이름 옆의 체크박스 |

### UI의 MCP 확장

- 식별자 목록용 텍스트 필드("Disabled extensions") 및 설치된 모든 플러그인의 참조 목록은 사용하지 않습니다.
- 별도의 자동 로드 확장 체크박스는 사용하지 않습니다.
- 대신 설정 페이지에 MCP 통합이 있는 설치된 플러그인 목록이 표시됩니다.
- 자동 로드와 동일한 규칙으로 확장 파일이 있으면 플러그인은 MCP 통합이 있는 것으로 간주됩니다([04-extensions.md](04-extensions.md) 참조).
- `redmine_mcp` 플러그인은 이 목록에 표시되지 않습니다.
- 각 항목에는 체크박스와 플러그인 이름이 있습니다.
- 목록 범례에는 사용자 정의 필드 폼의 프로젝트 및 tracker와 같이 Check all / Uncheck all 토글이 있습니다.
- 체크된 상자는 MCP가 활성화될 때 플러그인의 MCP 확장이 로드됨을 의미합니다.
- 체크 해제된 상자는 확장 파일이 있어도 플러그인 확장이 로드되지 않음을 의미합니다.
- 설치된 플러그인에 MCP 통합이 없으면 목록이 비어 있습니다. 표준 Redmine "no data" 메시지가 표시됩니다. Check all / Uncheck all 토글은 숨겨집니다.
- 이전에 저장된 비활성화된 플러그인 식별자는 계속 적용됩니다. 해당 체크박스는 체크 해제된 상태로 나타납니다.

### 설정 변경 시 동작

- MCP 비활성화는 `/mcp`에 대한 모든 요청을 즉시 차단합니다(HTTP 503).
- MCP가 활성화되면 Redmine 시작 시 확장이 로드됩니다. MCP가 비활성화되면 확장 자동 로드는 실행되지 않습니다.
- MCP 확장 체크박스 변경은 Redmine 재시작 후 적용됩니다.

## 로깅

### 로깅 대상

- 확장 로드 시작 및 종료;
- tools, resources, prompts의 성공적인 등록;
- 기존 도구 확장;
- 확장 등록 및 로드 오류;
- 도구 실행 오류;
- MCP 및 도구 접근 거부.

### 형식

- 메시지는 표준 Rails 로그에 기록됩니다.
- 각 메시지에는 `[redmine_mcp]` 접두사가 있습니다.
- 별도의 로깅 수준 설정은 사용하지 않습니다. 플러그인은 모든 메시지를 기록합니다.

## 엣지 케이스

- 모든 MCP 확장 체크박스가 활성화되었거나(또는 통합 플러그인이 없으면) MCP가 활성화될 때 발견된 모든 확장이 로드됩니다.
- MCP 확장 파일이 없는 플러그인은 목록에 표시되지 않으며 이 설정으로 비활성화되지 않습니다.
- 플러그인이 나중에 MCP 통합을 얻으면 이전에 비활성화되지 않은 경우 기본적으로 체크박스가 활성화됩니다.
- 저장된 비활성화 목록의 알 수 없거나 제거된 플러그인 식별자는 무시됩니다.
- 이전에 저장된 확장 자동 로드 플래그는 무시됩니다. 확장 로드는 Enable MCP를 따릅니다.
- 이전에 저장된 로깅 수준은 무시되며 설정 저장 시 제거됩니다.
- Read-only mode가 활성화되면 쓰기 도구는 `tools/list`에 남아 있지만(권한이 있는 경우) 호출 시 오류를 반환합니다. 결합 도구의 읽기 작업은 계속 작동합니다.

## 오류 처리

- 설정 오류는 Redmine 시작을 차단해서는 안 됩니다.
- 로깅 오류는 MCP 요청 처리에 영향을 주지 않습니다.

## 테스트 시나리오

1. MCP 비활성화 — `/mcp` 요청은 HTTP 503 반환.
2. MCP 활성화 — 요청이 처리됨.
3. MCP 통합이 체크 해제된 플러그인 — 재시작 후 도구 없음.
4. 설정 페이지에 로깅 수준 필드 없음. MCP 메시지는 Rails 로그에 기록됨.
5. 설정 페이지에 MCP 통합이 있는 설치된 플러그인 이름만 표시. 각각 체크박스 있음.
6. MCP 통합이 없는 플러그인은 설정 페이지에 표시되지 않음.
7. MCP가 비활성화되면 시작 시 다른 플러그인의 확장이 로드되지 않음.
