## Обзор

Плагин Redmine MCP предоставляет MCP-сервер (Model Context Protocol) внутри установки Redmine. AI-клиенты подключаются к единому HTTP-эндпоинту и получают доступ к данным Redmine через инструменты (tools), ресурсы (resources) и промпты (prompts).

Плагин включает базовый набор инструментов для работы с проектами, задачами и пользователями. Другие установленные плагины Redmine могут расширять MCP без изменения кода Redmine MCP.

## Цель

Обеспечить единый механизм интеграции Redmine с AI-системами, при котором:

- пользователь работает в рамках своих прав Redmine;
- разработчики плагинов могут добавлять собственные MCP-возможности;
- не требуется отдельный MCP-сервер или форк под конкретную установку.

## Основные сценарии

1. **Подключение AI-клиента** — администратор включает MCP, включает право `use_mcp` у нужных ролей и выдаёт API-ключ; пользователь подключает клиент (Cursor и др.) к эндпоинту `/mcp`.
2. **Работа с данными Redmine** — клиент вызывает инструменты для получения проектов, задач, пользователей.
3. **Расширение другими плагинами** — при установке плагина с MCP-расширением его инструменты автоматически появляются в общем списке.
4. **Администрирование** — включение/отключение MCP, включение MCP-интеграции отдельных плагинов.

## Затронутые области

- API (MCP через HTTP)
- Права
- Настройки
- Задачи
- Проекты
- Пользователи
- Форумы
- Plugins (расширения)

## Бизнес-правила

- MCP доступен только при явном включении в настройках плагина.
- Все операции выполняются от имени аутентифицированного пользователя Redmine.
- Запись через MCP идёт через модели Redmine: срабатывают model callbacks. Controller hooks (`controller_issues_*_save`, `controller_journals_edit_post` и т.п.) MCP не вызывает.
- Видимость данных соответствует правилам Redmine: пользователь не получает больше, чем видит в веб-интерфейсе.
- Имена инструментов и промптов имеют формат `<идентификатор_плагина>_<имя>`, например `redmine_list_projects`.
- `title` и `description` core tools публикуются на английском для выбора LLM и **не локализуются** через `en.yml`/`ru.yml` (исключение из i18n-стандарта для MCP tool catalog). Сообщения ошибок и UI настроек локализуются.
- Расширения от других плагинов не создают жёсткой зависимости: при отсутствии Redmine MCP сторонний плагин продолжает работать.

## Граничные случаи

- При выключенном MCP все запросы к `/mcp` отклоняются.
- При ошибке в одном расширении остальные расширения и базовые инструменты продолжают работать.
- Новые инструменты от расширений становятся доступны после перезапуска Redmine; клиенту MCP может потребоваться переподключение для обновления списка tools.
- В stateless-режиме каждый HTTP-запрос обрабатывается независимо; сессии между запросами не сохраняются.

## Обработка ошибок

- Ошибки аутентификации и авторизации возвращаются на уровне HTTP.
- Ошибки выполнения инструментов возвращаются в формате MCP с признаком ошибки.
- Ошибки загрузки расширений фиксируются в логе и не блокируют запуск Redmine.

## Тестовые сценарии

1. После установки и включения MCP клиент успешно выполняет `initialize` и получает информацию о сервере.
2. Пользователь с правом Use MCP и корректным API-ключом видит список доступных ему инструментов.
3. Пользователь без права Use MCP получает отказ при обращении к `/mcp`.
4. При установленном плагине-расширении его инструменты присутствуют в `tools/list` у пользователя с соответствующими правами.
