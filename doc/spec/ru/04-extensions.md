## Обзор

Redmine MCP предоставляет механизм расширения, позволяющий другим установленным плагинам Redmine регистрировать собственные инструменты, ресурсы, промпты и расширять существующие инструменты.

## Цель

Обеспечить единый подход к интеграции плагинов Redmine с AI без дублирования MCP-сервера и без изменения кода Redmine MCP.

## Затронутые области

- Plugins
- API
- Permissions

## Бизнес-правила

### Автоматическое обнаружение

- При старте Redmine (если MCP включён) система проверяет все установленные плагины.
- Плагин считается имеющим MCP-расширение, если в нём есть файл `mcp.rb` по одному из путей:
  - `lib/<plugin.id>/mcp.rb`;
  - `lib/<basename каталога плагина>/mcp.rb`;
  - `lib/<plugin.id без префикса redmine_>/mcp.rb`, если идентификатор начинается с `redmine_` (типичная схема вроде `redmine_advanced_checklists` → `lib/advanced_checklists/mcp.rb`).
- Плагин `redmine_mcp` сам себя не загружает как расширение.
- Плагины, у которых в настройках снят флажок MCP-расширения, пропускаются.
- Ошибка в расширении одного плагина не блокирует загрузку остальных, включая синтаксическую ошибку файла расширения.

### Регистрация инструментов (tools)

- Плагин-расширение может зарегистрировать любое количество инструментов.
- Каждый инструмент имеет: имя, описание, схему входных параметров, схему выходных данных, требование к правам, обработчик.
- Полное имя инструмента: `redmine_<идентификатор_плагина>_<имя>`, например `redmine_redmine_advanced_checklists_get_issue_checklists`, `redmine_advanced_search_semantic_search_issues`.
- Дублирование имён инструментов запрещено.
- Инструмент появляется в MCP только у пользователей с соответствующими правами.
- Issue-scoped инструмент расширения может требовать включённый модуль проекта Redmine (идентификатор модуля не обязан совпадать с идентификатором плагина). В `tools/list` такой инструмент виден, если у пользователя есть заявленное право хотя бы в одном видимом проекте с этим модулем. Без требования модуля достаточно права хотя бы в одном видимом проекте. Вызов всё равно проверяет конкретную задачу: видимость, право в её проекте и включённый модуль; иначе ответ «не найдено».
- Write-инструменты расширений в режиме read-only MCP не выполняют handler: отказ тот же, что у core write-tools.

### Расширение существующих инструментов

- Плагин может расширить уже зарегистрированный инструмент.
- Расширение может:
  - добавить дополнительные входные параметры;
  - выполнить код до вызова основного обработчика;
  - выполнить код после вызова и изменить результат.
- Несколько плагинов могут одновременно расширять один инструмент.
- Дополнительные параметры объединяются в общую схему входных данных.
- Имя дополнительного параметра не может совпадать с параметром core-инструмента или с параметром другого расширения того же инструмента.
- Итоговая схема нормализуется перед публикацией в `tools/list`.
- Порядок выполнения расширений соответствует порядку загрузки плагинов.

### Регистрация ресурсов (resources)

- Плагин может опубликовать ресурсы с уникальным URI. Повторная регистрация того же URI отклоняется.
- У ресурса обязателен обработчик чтения.
- Рекомендуемая схема URI: `redmine://<идентификатор_плагина>/<тип>/<id>`.
- Ресурс может требовать проверки прав; при отсутствии прав ресурс недоступен.
- Проверка прав получает URI и аргументы. Проект берётся из `project` / `project_id`, из URI (`project`/`project_id` в query или сегмент `/projects/:id`) либо из явного правила определения проекта, заданного расширением. `resources/read` передаёт в проверку `{uri: ...}`.
- Если проект в вызове указан, но не найден или недоступен текущему пользователю, доступ запрещается. Проверка «хотя бы в одном проекте» применяется только когда проект не указан (discovery с пустыми аргументами).
- Чтение ресурса возвращает содержимое в текстовом или JSON-формате.

### Регистрация промптов (prompts)

- Плагин может добавить промпты с именем, описанием, аргументами и обработчиком.
- Полное имя промпта: `redmine_<идентификатор_плагина>_<имя>`.
- Промпт доступен пользователям с соответствующими правами. Проверка прав получает аргументы вызова, включая `project` / `project_id`. Если проект указан, но не найден или недоступен, доступ запрещается; без указанного проекта действует то же правило discovery, что у ресурсов.

### События (hooks)

- Плагин может подписаться на события жизненного цикла MCP, например:
  - регистрация инструмента;
  - регистрация ресурса;
  - регистрация промпта;
  - завершение загрузки всех расширений.
- Ошибка в обработчике события логируется и не прерывает основной процесс.

### Зависимости

- Расширяющий плагин не обязан объявлять жёсткую зависимость от Redmine MCP.
- Рекомендуется проверять `RedmineMcp::ExtensionApi` / `mcp_extension_enabled?` перед регистрацией.
- Расширяющему плагину не требуется подключать gem MCP — достаточно API Redmine MCP.

### Возможности Extension API

Плагин-расширение через Extension API может:

- проверить, что MCP включён и расширение не отключено;
- зарегистрировать tool один раз (без дублирования при reload);
- зарегистрировать issue-scoped tool с типовой проверкой прав и поиском задачи; если задача исчезла к моменту handler, ответ — «не найдено», а не внутренняя ошибка;
- расширить существующий core-tool параметрами и before/after-обработчиками;
- зарегистрировать capability-режимы для `redmine_get_mcp_info` (например `issue_search.semantic`);
- вызывать REST API Redmine или плагина in-process от имени текущего пользователя через `internal_request` (`GET`, `POST`, `PUT`, `PATCH`, `DELETE`; целевой endpoint должен принимать API-auth); ошибки REST отображаются каноническими MCP-кодами без HTTP-статуса внутреннего запроса;
- публиковать `outputSchema` в формате envelope `{ ok, data | error }`.

Перечень методов Ruby API и примеры кода — в README плагина и в руководстве [mcp_tool_development.md](mcp_tool_development.md) (это dev-guide, не behavioral SPEC).

## Граничные случаи

- Плагин без файла расширения игнорируется.
- Файл расширения есть, но `require` падает — запись в лог, расширение не считается загруженным; регистрация tools — побочный эффект успешного `require`.
- Попытка расширить несуществующий инструмент — ошибка при регистрации расширения.
- Плагин со снятым флажком MCP-расширения в настройках не загружается, даже если файл расширения существует.
- После установки нового расширения требуется перезапуск Redmine; MCP-клиенту может потребоваться переподключение.

## Обработка ошибок

- Ошибка загрузки файла расширения — запись в лог, продолжение загрузки других плагинов.
- Ошибка регистрации инструмента при старте — запись в лог.
- Ошибка в `before`-обработчике расширения — прерывает выполнение инструмента.
- Ошибка в `after`-обработчике — логируется; результат основного обработчика сохраняется, если обработчик не изменил поток выполнения.

## Тестовые сценарии

8. Discovery ресурсов и промптов с пустыми аргументами остаётся доступным, если право есть хотя бы в одном проекте.
9. Плагин с `plugin.id` вида `redmine_*` и файлом `lib/<id без префикса redmine_>/mcp.rb` считается имеющим MCP-интеграцию и отображается в настройках MCP-расширений.
10. Issue-scoped tool с требованием модуля не попадает в `tools/list` у пользователя без ни одного видимого проекта с этим модулем, даже если право есть на другом проекте.
