## Обзор

Плагин Redmine MCP настраивается через стандартный интерфейс настроек плагинов Redmine. Дополнительно ведётся журнал работы MCP.

## Цель

Дать администратору контроль над включением MCP и включением MCP-интеграции отдельных плагинов.

## Затронутые области

- Settings
- UI
- Plugins

## Бизнес-правила

### Параметры настроек

Настройки доступны в **Администрирование → Плагины → Redmine MCP → Настроить**.

| Параметр | По умолчанию | Описание |
|----------|--------------|----------|
| Enable MCP | выключено | Включает или отключает эндпоинт `/mcp`. При включении автоматически загружаются MCP-расширения установленных плагинов |
| Read-only mode | выключено | Блокирует write-инструменты и write-действия |
| MCP-расширения | все включены | Флажки напротив названий установленных плагинов с MCP-интеграцией |

### MCP-расширения в UI

- Поле ввода списка идентификаторов («Disabled extensions») и справочный перечень всех установленных плагинов не используются.
- Отдельный флажок автозагрузки расширений не используется.
- Вместо них на странице настроек отображается список установленных плагинов, у которых есть MCP-интеграция.
- Плагин считается имеющим MCP-интеграцию, если для него найден источник расширения по конвенции автозагрузки: `mcp.rb` в плагине или встроенный файл `lib/redmine_mcp/extensions/<plugin.id>.rb` в `redmine_mcp` (см. [04-extensions.md](04-extensions.md)).
- Плагин `redmine_mcp` в этом списке не показывается.
- У каждого пункта — флажок и название плагина.
- В легенде списка — переключатель Check all / Uncheck all, как у проектов и трекеров на форме настраиваемого поля.
- Включённый флажок означает, что MCP-расширение этого плагина загружается при включённом MCP.
- Снятый флажок означает, что расширение этого плагина не загружается, даже если файл расширения существует.
- Если ни у одного установленного плагина нет MCP-интеграции, список пустой: показывается стандартное сообщение Redmine об отсутствии данных; переключатель Check all / Uncheck all не отображается.
- Ранее сохранённые отключения по идентификаторам плагинов продолжают действовать: соответствующие флажки отображаются снятыми.

### Поведение при изменении настроек

- Отключение MCP немедленно блокирует все запросы к `/mcp` (HTTP 503).
- При включённом MCP расширения загружаются при старте Redmine. При выключенном MCP автозагрузка расширений не выполняется.
- Изменение флажков MCP-расширений вступает в силу после перезапуска Redmine.

## Логирование

### Что логируется

- начало и завершение загрузки расширений;
- успешная регистрация инструментов, ресурсов, промптов;
- расширение существующих инструментов;
- ошибки регистрации и загрузки расширений;
- ошибки выполнения инструментов;
- отказы в доступе к MCP и инструментам.

### Формат

- Сообщения пишутся в стандартный лог Rails.
- Каждое сообщение имеет префикс `[redmine_mcp]`.
- Отдельная настройка уровня логирования не используется: плагин записывает все свои сообщения.

## Граничные случаи

- Если все флажки MCP-расширений включены (или плагинов с интеграцией нет), при включённом MCP загружаются все найденные расширения.
- Плагин без MCP-расширения (ни `mcp.rb`, ни встроенной интеграции) не отображается в списке и не отключается этими настройками.
- Если у плагина позже появится MCP-интеграция, его флажок по умолчанию включён, если этот плагин ранее не был отключён.
- Идентификаторы неизвестных или уже удалённых плагинов в сохранённых отключениях игнорируются.
- Ранее сохранённый флажок автозагрузки расширений игнорируется: загрузка расширений следует за Enable MCP.
- Ранее сохранённый уровень логирования игнорируется и при сохранении настроек удаляется.
- При включённом Read-only mode write-инструменты остаются в `tools/list` (если есть права), но при вызове возвращают ошибку; read-действия комбинированных tools продолжают работать.

## Обработка ошибок

- Ошибки настроек не должны блокировать запуск Redmine.
- Ошибки логирования не влияют на обработку MCP-запросов.

## Тестовые сценарии

1. MCP выключен — запросы к `/mcp` возвращают HTTP 503.
2. MCP включен — запросы обрабатываются.
3. У плагина с MCP-интеграцией снят флажок — его инструменты отсутствуют после перезапуска.
4. На странице настроек нет поля уровня логирования; сообщения MCP пишутся в лог Rails.
5. На странице настроек отображаются названия только тех установленных плагинов, у которых есть MCP-интеграция; у каждого есть флажок.
6. Плагин без MCP-интеграции на странице настроек не отображается.
7. При выключенном MCP расширения из других плагинов не загружаются при старте.
