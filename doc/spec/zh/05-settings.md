# 设置与日志

## 概述

Redmine MCP 插件通过标准 Redmine 插件设置界面配置。MCP 操作另有日志记录。

## 目标

让管理员能够控制 MCP 的启用以及为单个插件启用 MCP 集成。

## 涉及领域

- 设置
- UI
- 插件

## 业务规则

### 设置参数

设置在 **管理 → 插件 → Redmine MCP → 配置** 中可用。

| 参数 | 默认值 | 描述 |
|----------|--------------|----------|
| Enable MCP | 关 | 启用或禁用 `/mcp` 端点。启用时，自动加载已安装插件的 MCP 扩展 |
| Read-only mode | 关 | 阻止写入工具和写入操作 |
| MCP extensions | 全部启用 | 已安装且具备 MCP 集成的插件名称旁的复选框 |

### UI 中的 MCP 扩展

- 不使用标识符列表的文本字段（"Disabled extensions"）和已安装插件的参考列表。
- 不使用单独的自动加载扩展复选框。
- 设置页面显示已安装且具备 MCP 集成的插件列表。
- 若插件具有与自动加载相同约定的扩展文件，则视为具备 MCP 集成（见 [04-extensions.md](04-extensions.md)）。
- `redmine_mcp` 插件不在此列表中显示。
- 每项有复选框和插件名称。
- 列表图例有全选/取消全选切换，类似自定义字段表单上的项目和跟踪器。
- 勾选表示启用 MCP 时加载该插件的 MCP 扩展。
- 未勾选表示即使扩展文件存在也不加载该插件的扩展。
- 若无已安装插件具备 MCP 集成，列表为空：显示标准 Redmine "无数据" 消息；隐藏全选/取消全选切换。
- 先前保存的已禁用插件标识符继续生效：对应复选框显示为未勾选。

### 设置变更时的行为

- 禁用 MCP 会立即阻止所有对 `/mcp` 的请求（HTTP 503）。
- 启用 MCP 时，扩展在 Redmine 启动时加载。禁用 MCP 时不运行扩展自动加载。
- 更改 MCP 扩展复选框在 Redmine 重启后生效。

## 日志

### 记录内容

- 扩展加载的开始和结束；
- 工具、资源、提示的成功注册；
- 对现有工具的扩展；
- 扩展的注册和加载错误；
- 工具执行错误；
- MCP 和工具访问拒绝。

### 格式

- 消息写入标准 Rails 日志。
- 每条消息带有 `[redmine_mcp]` 前缀。
- 不使用单独的日志级别设置：插件写入其所有消息。

## 边界情况

- 若所有 MCP 扩展复选框均启用（或无插件具备集成），启用 MCP 时加载所有找到的扩展。
- 无 MCP 扩展文件的插件不在列表中显示，也不会被这些设置禁用。
- 若插件后来获得 MCP 集成，其复选框默认启用，除非该插件先前被禁用。
- 已保存禁用列表中的未知或已移除插件标识符会被忽略。
- 先前保存的扩展自动加载标志会被忽略：扩展加载遵循 Enable MCP。
- 先前保存的日志级别会被忽略，保存设置时移除。
- 启用只读模式时，写入工具仍在 `tools/list` 中（若用户有权限），但调用时返回错误；组合工具的读取操作仍可工作。

## 错误处理

- 设置错误不得阻止 Redmine 启动。
- 日志错误不影响 MCP 请求处理。

## 测试场景

1. MCP 禁用 — 对 `/mcp` 的请求返回 HTTP 503。
2. MCP 启用 — 请求被处理。
3. 未勾选具备 MCP 集成的插件 — 重启后其工具不存在。
4. 设置页面无日志级别字段；MCP 消息写入 Rails 日志。
5. 设置页面仅显示具备 MCP 集成的已安装插件名称；每项有复选框。
6. 无 MCP 集成的插件不在设置页面显示。
7. MCP 禁用时，启动时不加载其他插件的扩展。
